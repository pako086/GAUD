# Registro de cambios — GAUD

Este registro distingue los cambios de documentación de las funcionalidades de la aplicación. No se presentan como implementaciones funcionales aquellas que no fueron verificadas.

## Versión propuesta 0.1.0 — Documentación inicial

1. Se amplía el README con el objetivo del sistema, el problema que aborda, la arquitectura, las tecnologías y el estado actual.
2. Se documentan los requisitos funcionales y no funcionales con criterios de aceptación propuestos.
3. Se añaden diagramas para casos de uso, componentes y modelo de datos conceptual.
4. Se describe la responsabilidad del frontend, el backend PHP, la API JSON y la persistencia MySQL.
5. Se organiza el seguimiento del trabajo con referencias a Issues existentes y criterios para revisar la calidad.

## Pendientes de implementación o validación

- Ejecutar pruebas funcionales completas y registrar sus resultados.
- Comprobar la validación del lado del servidor y la autorización de endpoints.
- Revisar la configuración de base de datos y retirar credenciales de desarrollo antes de producción.
